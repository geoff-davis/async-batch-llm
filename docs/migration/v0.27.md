# Upgrading from v0.26.0 to v0.27.0

v0.27.0 is the last release before 1.0, and the last to support Python 3.10. It
changes several defaults, so review the sections below before upgrading. JSONL and
SQLite artifact schemas are unchanged, and v0.26 artifacts remain readable.

## OpenAIModel uses the Responses API

`OpenAIModel` now calls OpenAI's Responses API by default and sends `store=False`.
Most Chat-style request fields are translated for you (see
[Responses API](../OPENAI_INTEGRATION.md#responses-api-the-default-since-v027)).
To keep the previous behavior exactly, opt out:

```python
model = OpenAIModel.from_api_key("gpt-4o-mini", api_surface="chat_completions")
strategy = OpenAIStrategy(model, temperature=0.0)  # also restores the old temperature
```

- **SDK floor.** The `[openai]` extra now requires `openai>=1.66.2`, the first release
  that parses Responses reasoning summaries.
- **Rejected request fields.** `n`, `stop`, `seed`, `presence_penalty`,
  `frequency_penalty`, `logit_bias`, legacy `functions`/`function_call`, `stream` and
  `background` raise `ValueError` on the Responses surface. So do Chat content parts
  without a Responses equivalent. Use the opt-out if you rely on them.
- **Function-call-only replies** now succeed with `text=""`,
  `finish_reason="tool_calls"`, and the calls in `result.tool_calls`. A response
  parser that expects text should handle the empty string. The Chat surface still
  raises `EmptyResponseError`.
- **Other servers.** If you pointed `OpenAIModel` at a non-OpenAI server with
  `base_url` or `OPENAI_BASE_URL` (vLLM, a proxy, an Azure-style endpoint), switch to
  `OpenAICompatibleModel`, or to `llm("openai-compatible:<model>", base_url=...)`,
  which stay on Chat Completions. The alternative is `api_surface="chat_completions"`.
  There is no automatic fallback.
- **Checkpoints.** Automatic artifact identity for `OpenAIModel` now includes the API
  surface when it's the Responses API, so its results are stored and replayed
  separately:
  - A v0.26 checkpoint resumed with the new default re-runs its items; there is no
    error.
  - With `api_surface="chat_completions"` the identity is unchanged and v0.26 results
    replay.
  - If you pass an explicit `ArtifactIdentity`, it's used as-is: version it yourself
    if the surface change should invalidate replay.
- `OpenRouterModel`, `DeepSeekModel` and `OpenAICompatibleModel` are unaffected.

## Temperature is omitted by default

Built-in models, strategies, `llm()` and the `LLMModel` protocol now default to
`temperature=None`, which sends no temperature so each provider's default applies.
The old default was `0.0`, which some models or reasoning modes reject. Pass
`temperature=0.0` explicitly to keep the previous behavior.

## Error classification trusts types and status first

Application errors whose message mentions `429`, `quota`, a timeout or a connection no
longer start coordinated cooldowns or retries:

- Built-in programming errors (`ValueError`, `TypeError`, `KeyError`, …) are
  `logic_error`.
- An exception carrying HTTP 429 is a rate limit, with `Retry-After` honored.
- An exception carrying any other status is never a rate limit by message.
- `insufficient_quota` is a non-retryable `insufficient_balance` everywhere.
- Bare `"quota"` no longer signals a rate limit; `"quota exceeded"` does.
- Message matching still applies to untyped exceptions without a status.

If your code raised plain exceptions with rate-limit text to trigger a cooldown, raise
an exception with a `status_code = 429` attribute instead. `MockAgent`'s simulated rate
limit now carries `code = 429`.

## Configuration failures re-execute on resume

`token_estimator_required`, `token_estimation_error`, `token_estimate_exceeds_limit`
and `quota_scope_error` describe the run's configuration, not the item. They no
longer replay from artifacts, even under `ResumePolicy.REUSE_ALL`: after you fix the
estimator or quota scope, a resumed run re-executes those items. This applies to
records written by v0.26 too, on both JSONL and SQLite. No action is needed unless
you relied on `REUSE_ALL` to skip these items; filter them before submission instead.

## New in v0.27

- **Token and cost budgets:**
  `GuardrailConfig(max_total_tokens=..., max_total_cost=..., cost_function=...)`.
  See the [guardrails guide](../guardrails.md#token-and-cost-budgets). A `BatchResult`
  serialized with `termination.kind == "budget_exceeded"` can't be read by v0.26.
- **Custom endpoints in the factory:** `llm("openai-compatible:<model>", base_url=...)`.
- **Capacity-wait timing on deadlines and aborts:** an item whose capacity wait ends
  at a deadline or abort now reports that wait in `admission_wait_seconds`, and a
  deadline sets `timing.timeout_category == "admission_timeout"`. Dashboards keyed on
  `timeout_category` see the new value.
- **macOS** is now tested in CI and supported.

## Shared-policy sweep

Replay exclusion and permission to swallow an artifact error are distinct policies.

| Outcome | Checkpoint behavior | Replay eligibility | Prepare/append artifact error |
| --- | --- | --- | --- |
| Newly executed success | Append before publishing | Eligible when output is persisted | Propagates |
| Ordinary execution failure | Append before publishing | Eligible under `REUSE_ALL` | Propagates |
| `framework_total_item_timeout` | Append when a key can be prepared | Never eligible | Propagates |
| `batch_aborted` | Best-effort audit, including queued collateral items | Never eligible | Logged; terminal results survive |
| `batch_deadline_exceeded` | Best-effort audit, including queued collateral items | Never eligible | Logged; terminal results survive |
| `middleware_filtered` | Processor skips store access; direct store appends are permitted | Never eligible, including legacy filter records | Direct store calls retain their normal error behavior |
| `middleware_contract_error` | No checkpoint for the invalid request | No processor-created record | No store call |
| `artifact_preparation_error` | Failed item result without a usable checkpoint key | No processor-created record | Identity/input errors are routed per item; fail-fast remains opt-in |
| Completed artifact replay | Publish the fetched result without another guard check or append | Uses the selected eligible record | Lookup I/O/format errors still propagate |
| Caller cancellation | Propagates; no synthesized collateral-abort result | No new synthesized record | Not swallowed by `except ArtifactError` |

Scope of the best-effort rule is **prepare and append for the two batch-stop
categories only**. It does not suppress store-close errors or arbitrary exceptions.
An interrupted initial artifact preparation is not restarted solely for auditing.
Audit I/O has no new timeout, and one audit row per accepted queued item can make
abort draining expensive. These are documented limitations, not fixes left implied.

Callers checked:

- `build_item_record`, used by JSONL and SQLite append, derives eligibility from
  `NON_REPLAYABLE_CATEGORIES`.
- `is_non_replayable_record` is used by JSONL indexing and lookup and SQLite
  candidate selection and lookup. Both skip excluded legacy rows and fall back
  to an older compatible result. SQLite streams indexed candidates and closes
  its cursor; it does not load the complete history into memory.
- `ParallelBatchProcessor._process_accepted_item` controls both initially
  prepared checkpoints and audit-only preparation, and applies the distinct
  best-effort rule to prepare and append separately.
- Both middleware dispatch and the processor-override fallback validate using
  the item's type. Copying uses a shallow copy; neither invokes `__post_init__`.
- Batch submission, worker preprocessing, `process_prompts`, and `process_stream`
  share capacity configuration. Direct call/gateway warning behavior retains
  its existing `warnings.warn` path. Module-based suppression must match the
  attributed caller, not `async_batch_llm`.
